CredSeek API

Dokumentasi API aplikasi yang sama. Autentikasi Bearer JWT. User biasa butuh langganan aktif (`status: active|trial`). Admin & Dev bypass.

Auth

POST /api/auth/login

{
  "email": "user@company.com",
  "password": "secret123",
  "rememberMe": true
}

Response berisi token dan user.subscription.

GET /api/auth/me — header Authorization: Bearer <token>

Subscription

GET /api/subscription/plans — daftar paket (publik)

GET /api/subscription/me — status langganan user

POST /api/subscription/checkout

{ "planId": "starter" }

Membuat payment QRIS via Saweria. Response: payment.qrString, payment.id, payment.providerPaymentId.

GET /api/subscription/payments/:id — cek & sync status pembayaran

GET /api/subscription/payments — riwayat payment user

Jika belum berlangganan, endpoint produk mengembalikan 402 dengan code: SUBSCRIPTION_REQUIRED.

Search (contoh produk)

GET /api/search?q=example.com&filter=domain&page=1&limit=50

  • Guest: hasil terbatas & tersensor
  • Member aktif: hasil penuh
  • Member tanpa paket: 402
curl -H "Authorization: Bearer $TOKEN" \
  "https://YOUR_HOST/api/search?q=gmail.com&filter=domain&limit=20"

GET /api/admin/subscriptions

Payment provider (internal)

CredSeek memanggil:

  • Create: GET https://rasitech.org/saweria/?nominal=25000
  • Check: GET https://rasitech.org/saweria/cek.php?id=<paymentId> — status PENDING / sukses

Override via env SAWERIA_CREATE_URL dan SAWERIA_CHECK_URL. Paket custom: SUBSCRIPTION_PACKAGES_JSON.

Error codes

401 Unauthorized
402 SUBSCRIPTION_REQUIRED
403 Forbidden (role)
502 Payment provider error
